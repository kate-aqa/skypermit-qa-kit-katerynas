## Manual QA documentation

The companion repository [skypermit-qa-kit-katerynas](../skypermit-qa-kit-katerynas/README.md)
maintains manual test cases and test plans for this application. Keep the two
repositories side by side:

```text
gen-ai-skypermit-qa-kit/
├── ct-gen-ai-skypermit/
└── skypermit-qa-kit-katerynas/
```

The QA kit uses this application's requirements, contracts, business rules,
and UI selectors as read-only references. Its scope is manual QA documentation;
the scripts validate that documentation and report coverage rather than execute
application tests. The existing `api-automation/` scaffold is outside that scope.

The kit contains:

- `test-cases/auth/`: operator login, logout, and session handling.
- `test-cases/flight-request/`: flight-request state transitions and gate checks
  across operator and reviewer workflows.
- `.claude/`: case templates, worked examples, review guidance, and commands.
- `scripts/`: dependency-free Node.js utilities for structural validation and
  business-rule coverage. See the [script documentation](../skypermit-qa-kit-katerynas/scripts/README.md).

Cases use unique `E2E-<OP|REV|X>-<three digits>` IDs, stable `data-testid`
selectors in UI steps, and `skypermit/docs/...` citations with section references.
New or updated test plans should define scope, scenarios, preconditions, test
data, execution approach, and entry/exit criteria as appropriate.

Run documentation checks from the QA kit root with a Node.js version supporting
`import.meta.dirname`; no dependency installation is needed:

```bash
cd ../skypermit-qa-kit-katerynas
node scripts/validate-cases.mjs --app ../ct-gen-ai-skypermit
node scripts/rule-coverage.mjs --rules ../ct-gen-ai-skypermit/docs/06-business-rules.md
node scripts/rule-coverage.mjs --rules ../ct-gen-ai-skypermit/docs/06-business-rules.md --gaps
```

**Current validator limitation:** `validate-cases.mjs` resolves each literal
`skypermit/docs/...` citation beneath the `--app` directory. The command above
therefore looks under `ct-gen-ai-skypermit/skypermit/docs/` and can report missing
references even when the corresponding files exist in this application's
`docs/` directory. Reference-path resolution needs correction in the QA kit
before this command can provide a clean reference check for this layout.

Business-rule coverage counts citations asserted in a case's **Expected result**;
background references alone do not count. No coverage percentage threshold is
configured. Review expectations against the application's contracts and business
rules as well: structural validation does not establish logical correctness.
